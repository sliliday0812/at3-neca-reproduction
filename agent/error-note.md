# 失敗分析與處理

## 實際觀察

max3完成搜尋及讀取S1、S2，共3次工具呼叫，之後預算耗盡。S3尚未讀取、未寫簡報，外部審計13項中通過6項，final-state=false。執行器未發生工具錯誤。審計不屬於Agent在3步內自發調用validator，不能虛報為第四次成功工具呼叫。

## 已執行的完成路徑

同一任務、來源、schema、validator及rubric只改max_steps=6；前三次工具與參數完全相同，再讀S3、寫簡報、調用validator，共6次。實際3來源、6引用，13項全部通過。正式交付採此完成組；3步組的負結果保留以供受控比較。

## 原因與解讀邊界

工具每次只能讀一份來源，搜尋、寫作、驗證也各佔一步，因此完整路徑下限為6。這是事先可由流程推得、也經實際運行確認的資源不足，並非模型不理解論文。不能據此宣稱6步普遍最優或某模型能力提高。同一會話、固定順序、單次配對及來源摘編都限制外推；沒有測量模型token、生成延遲或API費用。

## 最容易出錯的地方

一是把未讀來源的引用當作已取證；二是只看二維再投影就宣稱三維臨床正確；三是把3DGR-CAR的學習初始化誤寫為無預訓練。來源主張ID、run內read_source回應及三篇正文定位共同約束這些風險。驗證器的字面匹配可擋住篡改，卻不能替代科學審讀或評估自由改寫品質。

## 已完成的異常檢查

六類情況均在臨時副本中被拒絕：未知引用、引用未讀來源、篡改已核對主張、修改來源檔、超額工具呼叫及run路徑越界；原始實驗記錄未因此變更。離線重放的兩組檢查結果與原始記錄一致。

## 下一測試與課程邊界

若老師另有正式材料，先用正式來源及validator重跑相同步數比較。進一步研究則可在新版本中加入陌生但相關來源、無關干擾與多次獨立重複，另行測試搜尋及引用能力；這些不是本輪已完成實驗。教師尚未確認自建來源／驗證器的課程接受範圍，此處明示，不把自建檢查冒稱教師驗收。
